# QA Audit: Fitzee

Date: 2026-08-07 | Scope: v1.0.0 application, puzzle content, local data, PWA, compliance, accessibility, performance, CI, and deployment readiness

## Summary

Fitzee's free, local-first v1 is technically ready to publish after the release
owner approves the expanded GitHub scope. No Critical or High defects were found.
The audit found three Medium release decisions or verification gaps and two Low
operational improvements. Two code/content consistency issues discovered during
the audit were fixed and covered by tests.

Automated validation is green: lint passes, 28 tests pass, the production PWA
build succeeds, and the current npm advisory service reports zero known
vulnerabilities. Chrome desktop and mobile emulation covered all four tiers,
pointer/tap/rotation play, rewards, Parent Zone gating and deletion, persistence,
seasonal content, localization, and a full offline reload. Actual Safari, Firefox,
VoiceOver, and TalkBack device testing remains outstanding.

## Findings

### 🔴 Critical — Must fix before launch

None found.

### 🟠 High — Should fix before launch

None found.

### 🟡 Medium — Fix soon

**[Compliance] Commercial launch still needs legal review and a dedicated parent contact**

- **Where:** `docs/COMPLIANCE.md` and `src/features/parent-zone/ParentPrivacy.tsx`
- **Problem:** The engineering controls match the repository specification, but the compliance document correctly states that it is not legal advice. The current parent support channel is the public repository, and the fixed typed `7 + 4` gate has not been approved by counsel for every intended market.
- **Fix:** Before marketing or charging for Fitzee, have qualified counsel review the parent gate and policy for the launch regions, publish a monitored parent-support email or form, and replace the pre-release contact copy.

**[Product] Optional Phase 4 monetization has no owner decision**

- **Where:** `ROADMAP.md` Phase 4 and `docs/PRD.md` open questions
- **Problem:** No price, billing model, payment provider, or decision to remain free has been authorized. Implementing payment collection without those inputs would invent a business decision and expand the privacy/compliance surface.
- **Fix:** Choose either a permanently free/deferred v1 or a Parent-Zone-only supporter/subscription model. If monetization is selected, provide the model, price/currency, provider, account configuration, refund/cancellation policy, and approved parent-facing copy before implementation.

**[Accessibility / Compatibility] Target-browser and assistive-technology hardware matrix is incomplete**

- **Where:** `docs/ARCHITECTURE.md#browserdevice-support-targets` and the release verification process
- **Problem:** Chrome desktop and 390×844 mobile emulation passed, including semantic-control checks, but emulation does not prove Safari/Firefox pointer behavior or actual VoiceOver/TalkBack announcements and gestures.
- **Fix:** Before broad promotion, run a documented smoke matrix on current Safari/iPadOS, Firefox, Edge, Android Chrome with TalkBack, and iOS/iPadOS Safari with VoiceOver. Cover onboarding, a high-piece puzzle, rotation, completion, Parent Zone, persistence, install, and offline reload.

### 🟢 Low / Polish — Nice to have

**[Performance] First-install offline cache is approximately 8.9 MB**

- **Where:** PWA precache generated by `vite-plugin-pwa`
- **Problem:** Caching all 32 unique 2048×2048 WebP scenes provides strong offline behavior but makes the first service-worker install heavier on slow mobile connections.
- **Fix:** Measure first-visit completion on target low-end tablets. If needed, generate smaller responsive sources or stage optional category packs, but only after resolving the PRD's offline-first asset-strategy question.

**[Maintainability] Service-worker build emits an upstream deprecation warning**

- **Where:** `vite-plugin-pwa` service-worker build
- **Problem:** The build succeeds, but its Rollup integration reports that `inlineDynamicImports` is deprecated in favor of `codeSplitting: false`.
- **Fix:** Track a compatible `vite-plugin-pwa` update and remove the warning when the plugin exposes the replacement; do not bypass the tested inject-manifest configuration solely to silence it.

**[Reliability] Seasonal availability used UTC and allowed stale direct routes — resolved**

- **Where:** `src/data/content/puzzleCatalog.ts`, `src/App.tsx`, and `src/features/gallery/MyPuzzlesScreen.tsx`
- **Problem:** A child near a local month boundary could see the wrong seasonal pack, and an old hash URL could open an inactive scene.
- **Fix:** Resolved in this audit: availability now follows the device-local calendar, inactive scenes are blocked from direct play/completion and hidden from My Puzzles, progress remains stored, and regression tests cover active/inactive months.

**[Privacy copy] Bundled-library wording was too broad — resolved**

- **Where:** `src/features/parent-zone/ParentPrivacy.tsx`
- **Problem:** Saying that no third-party scripts run could be read as excluding bundled open-source runtime libraries even though the intended guarantee is that no remote script or tracker runs.
- **Fix:** Resolved in this audit: the policy now accurately guarantees no advertising, analytics, tracking pixels, remote fonts, or remotely hosted scripts, and links the gated support channel.

## What's working well

- The four canonical age tiers are implemented with tier-specific piece counts, snapping, hints, timers, and required Puzzle Masters rotation without fail states for younger children.
- The catalog contains 128 valid puzzle variants across eight categories and four tiers, backed by 32 unique original 2048×2048 WebP scenes. Seasonal rotation is local and deterministic.
- Rewards are deterministic and idempotent: puzzle completion earns documented stars and stickers with no randomized or gambling-style mechanics.
- IndexedDB repositories isolate structured storage, degrade gracefully when persistence is unavailable, and support confirmed deletion of settings, progress, and rewards.
- Parent-only routes recheck a typed math gate, do not persist authorization, revoke access on exit or after more than 60 seconds in the background, and keep all purchase/data controls outside the child experience.
- Runtime source inspection found no fetch, beacon, cookie, advertising, analytics, iframe, identity, upload, or tracker integration. The CSP blocks external scripts, connections, frames, objects, and form submission by default.
- English and Filipino UI, speech-synthesis narration, large touch targets, forced-colors/high-contrast support, semantic buttons, keyboard placement, and reduced-motion behavior are present.
- The production PWA precaches 41 entries. A full Chrome reload with network emulation set to offline remained service-worker-controlled, rendered the app and images, and produced no runtime exceptions.
- CI runs lint, tests, and build; the Pages workflow builds with the repository base path and uses pinned action revisions.
